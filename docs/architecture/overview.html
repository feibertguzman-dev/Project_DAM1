Arquitectura

Arquitectura del Proyecto Cátedra UCN

MVVM con separación por capas, pensado para escalabilidad, mantenibilidad y claridad.

Volver a Documentación

Visión General

Aplicación Android nativa con Kotlin y Jetpack Compose

Cátedra UCN sigue una arquitectura MVVM (Model-View-ViewModel) con principios de Clean Architecture. Se busca una clara separación de responsabilidades entre UI, lógica de presentación y acceso a datos.

┌─────────────────────────────────────────────────────────┐ │ UI Layer │ │ (Jetpack Compose Screens, Theme, Navigation) │ └─────────────────────┬───────────────────────────────────┘ │ ┌─────────────────────▼───────────────────────────────────┐ │ ViewModel Layer │ │ (AuthViewModel, CatedraViewModel, AttendanceViewModel) │ └─────────────────────┬───────────────────────────────────┘ │ ┌─────────────────────▼───────────────────────────────────┐ │ Repository Layer │ │ (UserRepository, CatedraRepository, etc.) │ └─────────────────────┬───────────────────────────────────┘ │ ┌─────────────────────▼───────────────────────────────────┐ │ Data Sources │ │ Firebase Firestore, Firebase Auth, Room DB │ └─────────────────────────────────────────────────────────┘

Estructura de Paquetes

Organización clara por responsabilidades

com.example/ ├── MainActivity.kt # Punto de entrada de la aplicación ├── data/ │ ├── model/ # Modelos de datos (User, Catedra, Attendance) │ └── repository/ # Repositorios para acceso a datos ├── ui/ │ ├── screens/ # Pantallas Composables │ ├── theme/ # Tema, colores, tipografía │ └── viewmodel/ # ViewModels └── util/ # Utilidades (AuthHelper, GeminiClient, UiTranslator)

Flujo de Autenticación

Paso a paso del inicio de sesión

  • Inicio: MainActivity verifica el estado de autenticación con Firebase.
  • No autenticado: Se muestra LoginScreen con inicio de sesión Google.
  • Sin rol: RoleSelectionScreen permite seleccionar Estudiante/Profesor.
  • Autenticado: MainScreen carga el dashboard según el rol del usuario.

Roles de Usuario

Permisos diferenciados

  • STUDENT: Ver cátedras, registrar asistencia con evidencia, ver resúmenes IA.
  • TEACHER: Crear/gestionar cátedras, revisar asistencias, aprobar/rechazar y calificar.
  • ADMIN: Gestión completa del sistema.
